# Architecture (one page)

**What it is.** An agent that prepares a *sourced tender-readiness brief* for a procurement manager (primary reader) or a small supplier. A named human decides. It never awards, ranks bidders, advises to bid, or judges legality, and no tool exists that could.

**Flow.** intake (scope guard) -> plan (model chooses optional checks; process timeline is always selected by code) -> notice -> buyer history (buyer-id fallback; widens if thin) -> price benchmark -> counterparty quality check (buyer data validation) -> amendment check (detects proper handling vs overwrites) -> process timeline check (decision window from deadline to award) -> bidding window -> documents (borrowed Fetch server) -> investigate (loop mode only: when the data raises a signal, the model chooses a check from an allowlist) -> evidence (built by code) -> synthesize (model) -> verify (code, two attempts, template floor) -> independent filing checks -> `file_brief` (replay-checked) -> **stop** -> a person approves the exact brief fingerprint.

**Components.**
- **Own MCP server** (`wazi.server`): 14 read tools (`get_tender_notice`, `buyer_award_history`, `price_benchmark`, `peer_baseline`, `window_baseline`, `counterparty_quality`, `amendment_check`, `aged_items_check`, `budget_exposure`, `ppada_date_order_check`, `single_bidder_check`, `termination_check`, `publication_quality_check`, `process_timeline_check`) over a normalised SQLite store, and one acting tool (`file_brief`). Narrow tools, not a proxy of any portal.
- **Borrowed MCP server**: the official `mcp-server-fetch`, used to read tender document links. Robots.txt, redirects, content types and truncation are done and maintained by others; rewriting them would add risk and no value. Document text is untrusted data.
- **Orchestration**: LangGraph (explicit graph, bounded retries, human stop). **Model**: open weights, run locally by default (native Ollama API, or any OpenAI-compatible endpoint); free-tier aware (keys, backoff, quotas, cache); every brief records local or REMOTE.
- **Independent validation** (`wazi.validation`): code-based checks separate from the model (buyer consistency, tender integrity, findings structure). Results appear in the brief and manifest and are recomputed by `verify`; they are not a second human reviewer or identity control.
- **Gate, API, UI**: the approval gate is not an MCP tool, so the agent cannot approve itself. FastAPI plus one static page.

**Where the model sits.** Two or three narrow JSON jobs. It never calls tools, never sees raw tool output as truth, cannot approve, and cannot raise a signal the data did not raise.

**Guarantees enforced in code, not prompts.** Every finding cites evidence and a real citation (a field the cited record actually has); every number, in digits or words, must appear in its cited evidence; no verdict or advice language; award requests refused; untrusted text normalised to one line; document links to private addresses refused; a used-up quota stops the run instead of filing a fallback; replay at filing; decisions bound to the brief's content hash.

**Defensibility.** Each filing carries a hash-linked manifest (run, data version, code version, model and settings, every tool call with output hash, evidence, exact prompts and responses, cost, independent validation results). `verify` replays the tool calls, re-derives the evidence, re-checks every finding, and recomputes the independent checks. 104 mutants and the test suite guard these properties.

**Decisions considered and rejected.** A red-flag accuser (false-accusation risk) for a readiness brief. Fixed legal minimum windows (jurisdiction-dependent) for peer comparison. A free tool-calling agent on a small model for code-driven calls with model-written JSON. A multi-agent critic for one bounded loop plus a code verifier. LLM-as-judge for programmatic checks. A hosted-only model (procurement data often cannot leave the country) for local-first. The archived SQLite MCP server for Fetch. A React build for one static page.

**Known limits.** Synthetic data and a small case set; the real feed is untested. Number grounding is checked, meaning is not. Approval records a typed name, declared role/date, and brief fingerprint, but has no identity authentication; the printable fingerprint page is not implemented. No practitioner has reviewed briefs produced with the updated workflow. The strategic direction was informed by a simulated practitioner review and legal research, not validated through direct practitioner use. Tamper evidence ends where someone rewrites brief, manifest and decision together: anchor the fingerprint outside the folder.
